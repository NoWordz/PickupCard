## 规矩（Q4：限定子集，清单外报错）

- `tokens.css` 的 `:root` / `:root[data-theme=...]` 里**只放标量 token**，那是唯一会被
  `tools/css_tokens.py` 抽取的部分。清单外的自定义属性 → 抽取脚本**直接失败退出**。
  （静默失败最毒：上一版用 AUI 时 `radial-gradient` 不解析也不报错。）
- **几何与文字宽度一律不进转换**，就地写死。卡宽在游戏里跟名字走，浏览器里算不准 ——
  上一版想把这块也烘成确定值，就是"HTML 当贴图"死掉的根。
- **卡面参数不许在 `theme.css` 里再定义一遍**。v1 就是两边各存一份、重名 18 个键，
  于是改了 `tokens.css` 以后草稿页面纹丝不动 —— 而抽取器只管 `tokens.css`，不会拦。

## 怎么量"还原了没有"

```
python design/shot.py design/measure.html --geometry   # 出 design/measure.png + DOM 矩形
python design/compare.py design/measure.png <游戏测量页> --expect 4
```

游戏侧的测量页由 harness 自动产出：`./gradlew runClient -PharnessAuto=shot` 会多拍一张
`pickupcard-measure`（纯黑底、无辅助线、无读数）。

**为什么底色是纯黑**：投影是半透明的黑，叠在纯黑上等于没叠，自己就消失了。
于是"卡片之外就是纯底"成立，不用为测量往渲染里加任何"关投影"的开关 ——
而"投影关没关"已经有一个键了（`--pc-shadow-alpha`），再开一个口子就是第二真源。

`compare.py` 的客观门只管**结构项**：竖条宽/高、两处间隙、图标格宽、级差、固定的是哪条边、
**最新那张下缘距底边 / 卡高**（抓锚点）、**强调色自上而下**（抓"谁在最上面"）。
卡宽一类跟着字体走的数是内容项，只报不判 —— 浏览器和游戏的字体不是一个。

**后两条是 2026-09-17 补的，补的原因值得记**：四张卡的几何一模一样，"整堆被放到屏幕另
一头""新的和老的位置反了"这两类错误，逐张比结构**永远看不出来** —— 它们在门禁上一路绿灯
（这两类错误只在「锚点位置」与「颜色顺序」两条尺子上现形）。两条都做过**反例验证**：把锚翻回左上，
报 `+4.909 ← 差得多`；把 DOM 顺序倒过来，报颜色顺序反了。**新加的尺子要先量一个已知答案
的东西**，这条对门禁自己也成立。

## 动画：竖条是隧道口，卡片是火车

`animation.html` 里这条动画**不是**宽度从 0 长到自然宽 —— 那会把内容挤变形。
它是：**竖条原地出现（坐标全程不变）**，内容保持自身尺寸，从竖条后面平移到最终位置，
被竖条右侧的裁剪窗一点点"放出来"。

**锚在右下角**（2026-09-17 改）：最新的一张永远落在 `底线 - 卡高`（y = 202），
旧的被往上顶一格（26px），最老的那张在堆顶再升一格并淡出（`exitMs`，默认 320ms ——
游戏里就是这个键，两边只有一份时长）。
这样"入场口"是屏幕上**固定的一点** —— 眼睛不用满屏找新卡；而往上顶正好把最老的
推出安全区。`test_animation.py` 把这三条钉住了（连开三张，最新那张的 y 必须完全一致）。

（游戏侧原来还是**顶锚 + 新的在最上面**（往下载），和这里方向相反。2026-09-17 用户拍板
"游戏跟草稿走"，**已经翻完了**：`StackLayout` 下锚、`LayoutSettings` 默认 `RIGHT`、
退场改淡出，`measure.html` 与门禁也跟着翻了。）

两种出隧道方式可切：

| 方式 | 做法 | 谁先出现 |
| --- | --- | --- |
| 火车（默认） | 裁剪窗定宽，内容 `translateX(-100% → 0)` | 数字端先出 |
| 拉幕 | 内容不动，裁剪窗宽度 `0 → 自然宽` | 图标端先出（窗口从左边长起） |

两条实测（DOM 几何，非目测，`pytest design/test_animation.py` 可复现）：
**竖条 x 全程恒定**（火车档 342.2）、**内容自身宽全程恒定**（61.8）、
拉幕档的可见宽 0 → 70.4。**没有拉伸，只有位移。**

（`animation.html` 里"竖条固定在屏宽 75%"那段几何冲突已经被 M2 定案解决：
默认改成**右缘对齐**，内容再长也不出屏。）

### 游戏侧实现这个"隧道口"时踩过的两个坑（2026-09-17）

- **窗口左边是"竖条右缘 + 间隙"，不是卡片左缘。** SDF 那条曾经传 0、NanoVG 那条压根没有
  窗口 → 内容在坐标上滑出去了却没人挡，真机表现就是"卡片从左往右穿过竖条"。
  现在这条算式收在 `shared/.../style/RevealWindow.java`，三条绘制路径共用，`RevealWindowTest` 钉着。
- **曲线要写在"那两条进度的定义处"**（`CardTimeline.bar/content`）。原来的注释写着
  "easing 在渲染层做"，而渲染层一行都没做 → 竖条和内容都在匀速动（"很僵硬"）。
  现在 `CubicBezier.BAR` / `CubicBezier.SLOT` 各自钉在对应的那段上。

### 三个量出来的坑（都在 `test_animation.py` 里钉住了）

- **拿 `offsetTop` 量不到东西**：卡片是用 transform 摆的，而 `offsetTop` 只认排版位置，
  恒等于 0 —— 那样这套测试会全绿而什么都没测。要 `getBoundingClientRect`（眼睛看到的），
  再除回 `.stage` 那层 `scale(2)`。
- **`offsetWidth` 是四舍五入的整数**：右对齐会因此多伸出小半个像素。宽度要亚像素。
- **拉幕档不能用 `card.offsetWidth` 定右对齐**：窗口宽从 0 起跑，量到的是"还没展开"的宽，
  整张卡会被算到屏幕外面去。
